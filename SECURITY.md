# Security and privacy

- The installer changes user-scope `hooks.json` only after an explicit `-Approve`. It backs up existing files into a private user directory and leaves inline settings, plug-ins and project Hook files untouched. Existing JSON groups are kept and the installer stops on ambiguous HaloFlux ownership. Codex Hook trust still requires a separate review.
- Hooks run asynchronously with a one-second Codex timeout and always intend to return the neutral `{}` result. The HTTP request is bounded to 230 ms and delivery errors are ignored. An offline bridge drops events. Each event still incurs a short command launch.
- Codex provides its standard Hook payload on stdin. The forwarder temporarily parses it in memory and sends only the event type, timestamp, keyed pseudonyms for correlation, and a documented model outcome when present. It does not send prompts, tool arguments or output, code, file contents, project paths or credentials. Nothing is read from session transcripts. Pseudonyms are stable until the local signing key changes.
- The forwarder connects directly to `127.0.0.1`, including when Node's environment proxy support is enabled. The bridge binds that same address and checks the HTTP Host. Ingestion requires a local HMAC, rejects browser-originated requests and bounds input and replay tracking. SSE and the status endpoint expose recent minimized events and derived state in memory. Other local applications able to connect to the port can read those endpoints. Use ambient mode or disable the Hooks where activity timing itself is sensitive. The bridge persists no event log.
- Hook commands use absolute paths to a runtime with a private Windows ACL. The installer verifies the local Node.js signature and clears `NODE_OPTIONS` in its Hook command. The command includes a fingerprint of the installed code and Node.js so a reinstall with different contents produces a different Codex trust definition. Review the project source and runtime before trusting the commands. Use the disable/uninstall procedure before editing or upgrading the installed Hook code.
- Startup is manual. The bridge creates no service, scheduled task or registry startup entry. The published package contains no generated Hook configuration, credentials, backups, session files or private runtime binaries.

Use GitHub's private vulnerability reporting when available. Send a minimal description, affected version and reproduction steps. Keep actual Hook payloads, logs, backup files, keys and personal paths out of public issues.
